Проверяется доступность и результат действий в основных сценариях файлового

## Проверенные по исходникам наблюдения

### W01 — «Две панели» доступно, когда переключение запрещено (P2, исправлено)

Последовательность: запустить операцию или перечисление большой папки,
открыть «Вид», выбрать «Две панели» (либо F9). Обработчик возвращает
предыдущее состояние флажка и ничего не делает. Ожидается недоступная команда,
пока операция запрещает переключение, с восстановлением доступности по её
завершении.

До исправления `mainwindow_menus.cpp` создавал самостоятельный QAction;
`mainwindow_twopanel.cpp::togglePanels` отказывал при active operation либо
работающем filesystem scanner. `QtFileManagerCommands::RefreshActions` обновлял
зарегистрированные команды, но этот QAction в реестр не входил;
`MainWindow::refreshActions` также не задавал его доступность.
До исправления проверка обработчика предотвращала изменение панелей,
но пользователь видел доступную команду без результата.
Исправление внесено: команда включена в общий registry и source dispatch,
её доступность и checked-состояние обновляются вместе с остальными командами.
Проверка исполнения повторно читает состояние, поэтому устаревший enabled-флаг
не обходит запрет. Регрессия проверяет запрет при операции и восстановление
переключения после завершения; `large_list_window` также проверяет недоступность
во время асинхронной публикации и восстановление после неё. Linux PASS.
Дополнительный просмотр клавиатурных callers выявил прямые F9-вызовы из
адреса и исходного list handler. Они также направлены через общий source
dispatch; регрессия дополнена нажатием F9 во время публикации. Этот
дополнительный scope прошёл на Linux и macOS вместе с сохранением фокуса
редактирования адреса при успешном переключении.

### W02 — скрытый пароль может препятствовать созданию TAR (P2, исправлено)

Последовательность: в Add выбрать 7z, включить пароль, ввести разные значения
пароля и подтверждения, затем выбрать TAR и подтвердить создание. Поля пароля
скрываются и отключаются, однако проверка продолжает сравнивать их черновики
и отказывает с сообщением о несовпадении. Ожидается проверка только эффективных
параметров выбранного формата.

Основание: `createarchivedialog_encryption.cpp::SetEncryptionMethod` отключает
секцию для неподдерживающего шифрование формата, сохраняя checked-состояние;
до исправления `createarchivedialog.cpp::validateAndAccept` использовал только checked-состояние;
`CompressDialog.cpp::CheckPassword` сравнивает черновики независимо от формата.
При этом эффективный `password()` возвращает пустое значение для отключённого
поля. Сравнение с upstream OnOK показывает унаследованную безусловную проверку;
после адаптации скрываемой секции расхождение особенно неочевидно пользователю.
Исправление внесено: проверка использует эффективную доступность поля пароля,
сохраняя отключённые черновики. Поведенческие проверки охватывают смену на TAR
и снятие защиты без очистки черновиков. Linux PASS.

### W03 — отказ открытия адреса считался успешной навигацией (P2, исправлено)

При Enter на существующем, но не открываемом архиве Qt-адаптер возвращал
`S_OK`, игнорируя результат открытия. Исходный `OnNotifyComboBoxEnter`
поэтому переводил фокус из адреса в список даже после ошибки или отмены.
Та же потеря результата была в ветке обычной папки.

Исправление передаёт настоящий результат существующих владельцев открытия
и перечисления. Условие исходного обработчика и его перевод фокуса сохранены.
Добавлены поведенческие строки для отказа, ошибки и отмены: адрес сохраняет
фокус, файл не меняется, команды восстанавливаются, следующий корректный
переход работает. Linux PASS. Тест дожидается активации родительского окна
после модального прогресса, прежде чем проверять фактический keyboard focus.

### W04 — после загрузки большого адреса список не получал фокус (P2, исправлено)

При Enter в адресе большой папки или архива запрос перевода фокуса доставлялся,
пока список был отключён для асинхронной публикации. Запрос терялся, и после
завершения загрузки клавиатурное управление оставалось в адресе.
До исправления обе поведенческие строки воспроизвели ошибку.

Запрос передан существующему владельцу отложенного фокуса и ждёт готовности
списка. Новый ввод отменяет запрос, чтобы завершение загрузки не прерывало
редактирование. Проверки охватывают папку и архив с 1024 элементами, а также
новый ввод до завершения загрузки. Ошибки открытия по-прежнему сохраняют
фокус адреса. Это Qt-адаптация исходного posted-focus, а не новый алгоритм
навигации или перечисления.
Дополнительная диагностика native Windows выявила ошибку подготовки popup-теста:
Enter отправлялся до получения popup нативного фокуса. Трасса показала поздний
FocusIn выпадающего списка уже после перехода в файловую таблицу. Тест теперь
ждёт exposure и keyboard focus popup и отправляет клавишу через его QWindow;
ожидаемый фокус результата не устанавливается тестом. Временная трассировка
удалена. Это исправление стенда, а не ещё один продуктовый дефект.
