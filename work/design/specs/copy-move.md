# Копирование и перемещение

Статус: диалог назначения предложен для обсуждения. Согласованы предзаполнение
текущего пути при одной панели и отдельное поле имени для одного объекта.
Qt-реализация не изменена.
[Конфликты файлов](file-conflict.md) имеют отдельный макет и согласованный состав
действий. Прогресс и итог операции требуют дальнейшей проработки в этом сценарии.

## Назначение и состав

Диалог открывается командой «Копировать в…» / «Переместить в…» из меню
или контекстного меню списка. Обычные «Копировать» и «Вставить» в панели
действий используют буфер обмена и не открывают этот диалог.

Сверху — выбранный объект или количество объектов и известный размер. Полное
место источника доступно в подсказке, отдельной строки «Из: …» нет.
Для нескольких объектов список имён раскрывается по запросу и
прокручивается внутри ограниченной области. Неизвестный размер не заменяется
нулём или размером части выделения; расчёт не задерживает открытие диалога.

Далее — редактируемое назначение и «Выбрать…». В одной панели подставляем
текущий путь: уточнение пользователя 4 ноября, заменившее прежний пустой ввод.
Для двух панелей предлагается текущее место другой панели, если оно поддерживает
запись. Кнопка «Другая панель» позволяет вернуться к нему после ручного ввода.
При недоступной записи кнопка отключена; предзаполнение остаётся текущим путём.

Рядом доступны недавние назначения. Выбор меняет только поле, без запуска
операции. История пополняется после принятия диалога; отмена не меняет её.
Нужна совместимость с существующей историей, где встречаются также полные
пути файлов: такие значения нельзя автоматически превращать в каталоги.

Для одного объекта согласовано отдельное «Имя в назначении», изначально
совпадающее с исходным. Это позволяет создать копию с новым именем в текущей
папке. Для нескольких объектов поле не показывается. Разделение имени и пути
принято пользователем 4 ноября.

Нижняя строка: «Отмена», «Копировать» / «Переместить».
Основное действие не запускается при пустом назначении, пустом имени,
отсутствии объектов, известном запрете записи или переносе из источника только
для чтения. Совпадение исходного и конечного места без изменения имени
показывает пояснение рядом с полем. Существующая операция проверяет итоговый
путь и возможности источника/назначения; форма не заменяет эти проверки.

## Переходы и клавиатура

- При открытии выделен путь назначения, чтобы сразу заменить его вводом.
- «Выбрать…» открывает системный выбор папки с текущим значением поля.
  Принятие подставляет выбранный путь; отмена сохраняет введённый текст и имя.
  Фокус возвращается к назначению. Макет использует демонстрационный выбор мест.
- Tab последовательно проходит интерактивные элементы формы. Список выбранных
  объектов не перехватывает обычные стрелки ввода пути.
- Enter подтверждает доступное основное действие; Escape / платформенная
  команда отмены закрывают диалог. Выделение и место источника сохраняются,
  фокус возвращается в список. История, буфер обмена и файлы не меняются.
- Повторный вызов создаёт новое предложение из текущей панели и выделения,
  а не возвращает незавершённый ввод отменённого диалога.
- Подтверждение фиксирует источник и назначение для операции, затем показывает
  её ход. Конфликт запрашивается только при фактическом обнаружении. Успех,
  пропуск, частичный результат, ошибка и отмена не должны смешиваться.

## Компактность и платформы

Основная форма не требует постоянно видимого списка всех файлов. Длинные имена
и источник переносятся, назначение прокручивается внутри текстового поля.
При раскрытии списка или истории кнопки остаются достижимы прокруткой диалога.
Структура общая, системный выбор папки, шрифт, размеры контролов, модальность
и порядок кнопок следуют платформе. В этой сессии оцениваем браузерный macOS-макет;
это не приёмка Qt на macOS, Windows или Linux.

## Граница реализации

Существующие владельцы: [CopyDialog](../../../src/dialogs/copy/CopyDialog.cpp)
и [маршрутизация операции](../../../src/filemanager/AppCopy.cpp).
Исходный контракт: [Copy/Move](../../../docs/ui-layout-contracts/copy-move.md),
ресурсы upstream зафиксированы в существующем
[baseline](../../../docs/ui-reference/copy-dialog.reference.json).

Не заменяем разбор пути, нормализацию, историю, проверки доступности,
маршрутизацию FS / архив / streams и публикацию результата новой логикой формы.
Назначение в открытой другой панели должно сохранять идентичность провайдера.
Нельзя определять тип назначения только по расширению файла.

Отдельное имя потребует согласованного преобразования в существующий контракт
назначения: неизменённое имя не должно ломать маршрут в архив другой панели,
а старое значение истории с именем файла нельзя дополнить вторым именем.
Для неподдерживаемого маршрута переименование не предлагается.

В текущем приложении при одной панели внутри архива начальное назначение
сводится к существующему пути на диске. Решение «текущий путь» пока показано
для обычной папки; при проектировании архива отдельно определим понятный
пользователю начальный путь, сохраняя доступные маршруты операции.

## Проверки будущей реализации

- Одна и две панели; Copy и Move; один объект и большое выделение.
- Выбор папки, отмена выбора, ручное изменение пути, история и повторный вызов.
- Копия одного файла с новым именем, Unicode и значимые пробелы в пути.
- FS, архив и доступный только для чтения источник; неподдерживаемое назначение.
- Успех, отказ, конфликт с Skip/Cancel, частичный результат; отсутствие потери
  источника при неподтверждённом переносе.
- Компактная форма, длинные строки, клавиатура и возврат исходного выделения.

Макет проверяет переходы и компоновку на демонстрационных данных. Он не выполняет
файловые операции и не доказывает поддержку маршрутов или целостность данных.
