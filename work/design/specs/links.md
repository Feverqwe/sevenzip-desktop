# Создание и изменение ссылок

Актуализация макета v64. Редактор ссылок исключён. Поддержанные операции чтения и копирования ссылок сохраняются.
Описания прежних поверхностей ниже сохранены для справки. См. [план интерфейса](implementation-scope.md).

Статус: автономная проработка 5 ноября 2026 после rebase на e16690f7.
Новые формы и переходы реализованы только в HTML-макете. Данные файлов,
существования целей, томов и прав демонстрационные; это не native-проверка ОС.

## Две явные задачи

«Создать → Ссылка…» создаёт новый объект с собственным именем и папкой.
Выбранный файл/папка предлагает назначение. Даже если выбранная запись сама
является ссылкой, эта команда не меняет её незаметно. Новая ссылка на такую
запись и изменение уже существующей — разные намерения.

У распознанной символической ссылки в контекстном меню есть «Изменить ссылку…».
Форма показывает захваченное имя/папку, текущее назначение и вид. Изменяется
назначение этого объекта; смена места в другом окне не подменяет объект запроса.
Для обычного файла с несколькими жёсткими именами такого действия нет: у hard
link нет единственного записанного «оригинального пути», который можно заменить.

Архивные/виртуальные записи не получают запись в исходный контейнер через этот
маршрут. Используется обычный filesystem provider и его capabilities. Для
создания достаточно возможности записать новый объект в выбранную папку;
read-only целевой файл не является сам по себе разрешением/запретом всей операции.
Действительные ограничения прав/томов определяет native владелец.

## Создание

Папка ссылки с системным выбором, имя ссылки, назначение с выбором файла/папки,
тип и короткое объяснение его смысла. Начальное назначение — захваченный объект;
начальная папка — другая доступная обычная панель, если она видна, иначе текущая.
Предложенное имя редактируемое, сохраняет расширение файла. Начальный тип следует
существующему владельцу/профилю: текущий native выбирает hard link для файла
и подходящую ссылку на папку. Макет не вводит глобальный новый тип по умолчанию.

Имя и папка обозначают место новой записи; назначение — то, на что она указывает.
Не используем двусмысленные «Источник»/«Путь создаваемой ссылки» с обратным
порядком старых from/to. Кнопки «Отмена», «Создать ссылку».

Виды определяются платформой и capabilities:

| Тип | Представление и существенное ограничение |
| --- | --- |
| Символьная ссылка | Указывает на путь; файл/папка классифицируются native владельцем |
| Жёсткая ссылка | Другое имя того же файла, в пределах поддержанного тома; не отдельная копия |
| Junction | Только поддержанная Windows/FS, папка и подходящий абсолютный путь |
| WSL | Поддержанная Windows-служба и цель в формате WSL |

Неприменимые Windows-типы скрыты на macOS/Linux, а не занимают несколько
неработающих строк. Hard link на папку не предлагается. У отсутствующего
назначения символической ссылки можно уточнить «Файл»/«Папка», когда это нужно
native классификации, особенно для Windows. Каталог возможностей не угадывает
существование цели по расширению или видимой строке «Тип» в таблице файлов.

Смена типа не должна молча менять назначение, создавать копию вместо ссылки
или заменять отказавшую hard link символической. Ошибка EXDEV/прав объясняется,
параметры сохраняются. Разрешение системных привилегий остаётся за ОС;
автоматического повышения прав или изменения системных настроек форма не обещает.

## Относительное и отсутствующее назначение

Raw назначение символической ссылки сохраняется без trim, cleanPath и
канонизации: `../Материалы/../Файл`, пробелы и символы не являются черновой
строкой, которую можно произвольно переписать. `symlink/..` нельзя безопасно
свернуть простым удалением сегментов. Относительное назначение отсчитывается
от папки самой ссылки; изменение папки новой ссылки может изменить его смысл,
поэтому это правило написано рядом с выбором типа.

Несуществующий путь допустим для символической ссылки. Показываем его состояние,
но не объявляем ошибкой, мешающей созданию. Hard link требует существующего
подходящего файла. Для hard link относительный пользовательский путь сначала
разрешает native filesystem-служба в явно показанном контексте папки ссылки;
не полагаемся на случайный рабочий каталог процесса. Это адаптация существующего
вызова, а не обещание хранить относительный путь внутри hard link.

WSL-путь не проходит автоматическое преобразование в Windows-разделители.
Обычная Windows-панель выбора не подставляется как универсальный выбор пути
внутри Linux-окружения: в макете для WSL остаётся raw ввод без такой кнопки.

## Изменение существующей ссылки

Имя/папка зафиксированы карточкой источника; тип не меняется скрытым пересозданием
объекта другого вида. Основное поле — назначение. Кнопки «Отмена», «Сохранить».
Типовая конвертация file symlink/directory symlink/junction — не побочный эффект
редактирования назначения; если текущий native вариант её не допускает,
показываем точную причину. Создать другой вид можно отдельным новым объектом.

Пустое назначение блокирует подтверждение, включая Enter. Оно **не** означает
удаление ссылки или сброс reparse data. Это намеренное отделение от старого
обработчика, где пустое `to` может удалить POSIX-ссылку или Windows reparse data.
Удаление самого объекта остаётся отдельной обычной командой с её подтверждением;
не удаляем по такому действию содержимое назначения.

Недоступная цель и непрочитанное назначение — разные ситуации. Повреждённую
ссылку с достоверно прочитанным raw target можно перенаправить. Если raw значение
не прочитано, не воспроизводится либо не проходит обратимое преобразование
кодировки/контрола ввода, Save недоступен; не подставляем пустоту или U+FFFD с возможностью
записи. Исходный объект и его байты остаются нетронутыми.

Если значения не изменились, Save закрывает форму без пересоздания ссылки.
Отмена/Escape не меняют ссылку, её назначение или другие имена hard-linked файла.
И успешное изменение, и отмена возвращают фокус к соответствующей записи.

## Занятое имя, гонки и результат

Создание несёт намерение «новая отсутствующая запись». Занятый обычный файл,
папка, пустой файл, symlink или dangling link не заменяются. Ошибка предлагает
другое имя/папку и сохраняет ввод. Нет implicit conversion обычного inode в
reparse point, Replace и общего конфликта копирования.

Изменение несёт ожидаемую идентичность конкретной ссылки и исходное назначение.
Если другой процесс/окно изменил, удалил или заменил объект, применение
останавливается. Пользователь заново открывает актуальный объект, а не
подтверждает старым Save перезапись чего-то другого. Проверка выполняется на
native границе записи; frontend snapshot не устраняет TOCTOU.

Быстрое создание/изменение не открывает фиктивную долгую операцию с процентами.
Пока выполняется реальный запрос, форма сохраняет значения и показывает общий
индикатор неизвестного объёма без выдуманного процента. Повторное подтверждение
недоступно. Если текущий системный вызов неотменяем, Cancel/Escape не изображают
успешную отмену уже начатой записи; ждём достоверного результата. До запуска
обычная отмена свободно закрывает черновик. Ожидание не должно блокировать
другие окна приложения: транспорт и pending-владелец переживают их закрытие.
Ошибка
остаётся в форме с raw вводом и возможностью повторить; успех закрывает её,
обновляет затронутые панели и показывает/выделяет новую запись, когда она видна.
Назначение доступно в технических сведениях свойств и копируется целиком.
У крупного элемента символической ссылки есть отметка ссылки, общая с каталогом.

Отображаемые имя/тип не являются файловыми capabilities. Модель записи отдельно
передаёт directory/link kind, identity и native свойства. Обычное открытие
использует существующий provider-маршрут, свойства различают саму ссылку и цель,
а изменение/удаление работают с объектом ссылки. HTML не имитирует все переходы
реальной файловой системы по цепочкам ссылок и разрешение mount namespace.

## Владельцы и доработки для Qt

После rebase проверены актуальные
[вызов CApp::Link](https://github.com/Feverqwe/7zip-qt-port/blob/ed197ad23afd33abf073e9fae1bb6fa113640e43/src/filemanager/AppLink.cpp),
[LinkDialog и native функциональные ветви](https://github.com/Feverqwe/7zip-qt-port/blob/ed197ad23afd33abf073e9fae1bb6fa113640e43/src/dialogs/link/LinkDialog.cpp),
[обёртка ввода](https://github.com/Feverqwe/7zip-qt-port/blob/ed197ad23afd33abf073e9fae1bb6fa113640e43/src/dialogs/link/qtlinkcontrols.h),
[состав платформенных типов](https://github.com/Feverqwe/7zip-qt-port/blob/ed197ad23afd33abf073e9fae1bb6fa113640e43/src/dialogs/link/qtlinkpresentation.cpp),
[POSIX создание/изменение и copy/rename](../../../src/fileops/links/qtlinkservices.cpp),
[native hard link](../../../src/fileops/native/FileDir.cpp),
[Windows/WSL link data](../../../src/fileops/native/FileLink.cpp).
До rebase прочитаны оригинальные LinkDialog.rc и полный OnButton_Link из
локального source.tar.xz. Изменение базы перенесло владельцев представления
под dialogs/link и вынесло CApp::Link, но не заменило выбранные алгоритмы.
Нового импорта исходников и C++ изменений в этой итерации нет.

Переиспользуем native создание, чтение, разбор и запись ссылок. Нужны typed
намерения CreateNew/RetargetExpectedObject, разделённый ввод output path/raw
target, native классификация и ошибки, отказ от empty-target удаления в Save,
identity-aware запись и целевое обновление панелей. Текущий CApp::Link сам
выбирает edit при выбранной ссылке; новый явный Create не может слепо вызвать
тот же маршрут с прежним набором аргументов.

Текущий QtSetPosixLink делает private staging и rename для изменения, но его
проверка типа перед rename сама не гарантирует ожидаемую идентичность при гонке.
Create также нельзя передать в ветвь автоматического retarget уже появившейся
ссылки. На Windows exclusive reservation/ownership проверяются до SetReparseData,
а cleanup после отказа удаляет только собственный объект. Сохраняем полезные
native тела и усиливаем узкую границу владения, без второго link implementation.

CQtLinkCombo сейчас преобразует разделители в обоих полях; новый raw target
WSL/POSIX нельзя пропускать через такой общий normalizer. Известная проблема
обёртки — не доказательство отсутствия поддержки формата в native FillLinkData.

Компоненты: контекстная поверхность, SourceSummary, SystemPathField, raw target
как его специализированный контракт, обычные имя/тип, InlineMessage, ActionBar.
Типизированные данные и операции принадлежат файловому модулю, не виджету.

Проверки реализации: реальные symbolic file/folder и hard link на owning ОС;
relative/absolute/missing target; Unicode/пробелы/`symlink/..`; picker Cancel;
hard cross-volume, unsupported type/FS/permissions без fallback; occupied entry
включая dangling link и пустой обычный файл; Create выбранной ссылки не retarget;
edit/no-op/Cancel/пустой Enter; read-only и non-roundtrippable target;
смена идентичности между чтением и записью, failure сохраняет старую ссылку/цель;
Windows junction/WSL и raw separator round-trip на Windows; обновление обеих
панелей, свойства/clipboard, компактные/длинные значения и обе темы.

Windows-состояния HTML проверяют состав формы в общей оболочке макета, не
нативную геометрию Windows и не работоспособность ссылок. Runtime-приёмка Qt
на платформах выполнения пока не проводилась.
