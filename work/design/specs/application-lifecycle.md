# Сервис, закрытие окон и выход

Автономная проработка 5 ноября 2026, service-v54. Это продуктовый контракт
и HTML-сценарий; он не подтверждает изменение Qt lifecycle. Закрытие файлового
окна уже согласовано как независимое от самостоятельной операции.

## Меню «Сервис»

«Подключить текущую папку для чтения…», «Подключённые папки…», «Временные
файлы…», «Тест производительности…», «Настройки…». Сервис больше не является
скрытой кнопкой прямого запуска benchmark. Общие окна доступны независимо
от выделения. Создание подключения доступно только для поддерживаемого
открытого источника; обычная папка и корневой namespace не получают эту команду.
Native capabilities имеют приоритет над демонстрационным признаком archive.

Подключение захватывает текущий источник и внутреннюю папку при вызове,
а не использует пример «Проект.7z». Не подменять папку источника его физическим
родителем. Дальше действует [контракт ограниченных источников](restricted-sources.md).
HTML переносит этот контекст в форму и показанный результат одного подключения;
это демонстрация, а не общий системный mount registry и не настоящее подключение.

На macOS общие настройки также доступны через меню приложения и ⌘,. About
и лицензии остаются отдельными окнами. Встроенная справка по решению пользователя
не возвращается. Набор тестов и временные файлы сохраняют существующих владельцев;
меню не запускает консольный процесс вместо GUI-команды движка.

## Закрытие файлового окна

Закрытие окна и последней вкладки закрывает только этот файловый контекст.
Задача, пароль, конфликт, временный файл и подключение не становятся бесхозными.
Операция может закончиться позже и публикует результат своему владельцу;
закрытому виджету не доставляется обращение через сохранённый raw pointer.
Окно другой папки продолжает работать. Сворачивание операции после закрытия
последнего файлового окна не открывает новую домашнюю папку само по себе.

Список операций и их собственные окна остаются доступны. Новое файловое окно
можно открыть явно; при отсутствии активной папки оно открывает домашнюю.
Новый запрос файлового окна отменяет отложенный выход приложения.

## «Завершить Sevenzip»

Команда меню и платформенная клавиша выхода вызывают один запрос уровня
приложения. При обычных файловых окнах и отсутствии незавершённой работы
выход сохраняет сессию и закрывает окна без отдельного подтверждения.
Дальше восстанавливаются прежние окна/вкладки по основному контракту.
Не сохраняются пароли, ключи, незапущенные формы и разрешения на recovery.

Если открыты незапущенные формы, показывается краткое подтверждение их закрытия
без применения. «Отмена» сохраняет ввод и возвращает фокус. Подтверждение
закрывает формы и завершает приложение. Это не отмена уже запущенной операции
и не сохранение настроек вместо нажатия «Сохранить».

Если есть работающие операции или результаты, требующие просмотра:

- «Отмена» сохраняет рабочее пространство.
- «Показать операции» возвращает к одной из задач для проверки или остановки.
- «Продолжить операции» закрывает файловые окна, сохраняя окна задач и их вопросы.

Вопрос сообщает, что приложение завершится после окончания работы и просмотра
результатов. Не добавляем здесь принудительное убийство процессов или фиктивную
общую отмену: остановка принадлежит конкретной операции. Полный успех может
закрыться автоматически; пропуски, ошибки, отмена и результаты расчётов остаются
до закрытия пользователем. Пока есть такой результат, выход не выдаётся за
завершённый. Начатое до запроса выхода сохраняется, новые файловые действия не
запускаются от исчезнувшего окна.

Снимок сессии берётся до закрытия окон. Повторный запрос выхода во время
работы не заменяет его пустым набором. Восстановление сессии не возобновляет
операции автоматически и не считает неподтверждённые результаты успешными.
Системное завершение сеанса, crash и потеря питания не обещают orderly shutdown.

## Владельцы и конкретные границы

Прочитаны upstream Tools/Help из локального resource.rc и соответствующий
native dispatch; текущие MainWindow menus, mount commands и benchmark workflow;
CloseFileManager, MainWindow::closeEvent/quiesceOperations; полностью launcher,
process, endpoint и POSIX child reaper. Внешнего кода не импортировали.

На e16690f7 launcher принадлежит приложению, observer не завершает независимую
задачу. POSIX spawn создаёт самостоятельный процесс, а Windows использует
существующий native process owner. Endpoint захватывает проверенный request
до accept; потеря IPC после accept не отменяет работу. Потеря канала до приёма
задания — другая ошибка и не подтверждает запущенную операцию. Возврат PID сам
по себе не заменяет acceptance/result. Эти существующие границы сохраняются.

Однако текущий MainWindow close отменяет и ждёт файловые in-process workers.
Поэтому новый контракт требует переноса их lifecycle из окна к владельцу
операции. Нельзя выполнить его простым отключением quitOnLastWindowClosed.
Живые worker, scanner, archive resource, временный вход и ожидающий callback
должны оставаться согласованными; их владелец подтверждает завершение.

Quit coordinator сначала запрашивает возможность закрытия всех владельцев,
включая подключения и внешние сеансы. Существующий CanCloseMounts не обходится:
подключение нельзя автоматически отключать принудительно из общего Quit.
Ошибка или veto возвращает к владельцу до разрушения файловых окон. Защищённая
временная копия сохраняется по контракту [внешних сеансов](external-file.md),
а не удаляется ради выхода. Native подготовка/запуск операции до acceptance
тоже удерживает владельца до определённого результата.

В HTML benchmark имеет отдельную модель worker, поэтому выход при активном
тесте возвращает к его окну и требует штатной остановки. Нет завершения worker
по таймеру. При реализации включить его в общую проекцию независимых задач;
существующий native GUI benchmark уже использует 7zG. Макет не является
подтверждением глобальной регистрации benchmark/mount/external владельцев.

## Компоненты и проверка

Меню собирается из MenuSurface/MenuItem; вопрос выхода — из DialogSurface,
InlineMessage и ActionBar. Общий QuitCoordinator владеет запросом выхода,
снимком сессии, preflight и ожиданием; файловый виджет не перечисляет процессы
и не исполняет архивные команды. Escape и начальный фокус безопасно возвращают
в исходный контекст. Подложка вопроса не принимает ввод; Tab остаётся в вопросе.

Браузером проверены маршруты Service, захват вложенной папки для подключения,
выключенная команда в обычной папке, выход без операций и восстановление,
отмена с открытой формой, работающая операция без файловых окон, повторный Quit,
явное новое окно, ошибочный итог и его закрытие, возврат к занятому benchmark.
Вопрос помещается в 480×640 dark. Это evidence HTML, не native shutdown test.
Для реализации нужны observable проверки: owner veto, два окна, старт/accept,
пароль/конфликт при закрытом окне, поздний результат, ошибка/cancel/success,
живое подключение, внешняя копия и восстановление без секретов.
