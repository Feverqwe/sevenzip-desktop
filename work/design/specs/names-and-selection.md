# Создание, имена, маски и комментарии

Актуализация макета v64. Имя новой папки вводится прямо в списке. Создание пустого файла, редактирование комментария и маски исключены.
Описания прежних поверхностей ниже сохранены для справки. См. [план интерфейса](implementation-scope.md).

Статус: проработано автономно по поручению пользователя 5 ноября 2026, v40.
[Макет](../index.html?review=names-v40#rename). Команды доступны в соответствующих
меню главного окна; обычное переименование остаётся inline в файловом списке.

## Общий блок и разные задачи

Контекстная поверхность содержит подписанное поле, связанную ошибку и строку
действий. Исходное место не занимает отдельную строку; полный путь доступен
в подсказке формы. Визуальный блок общий, но назначение команды задаётся
типом, а не текстом заголовка или переведённой подписи кнопки. История значений
может использовать существующий native combo owner; её наличие не заставляет
показывать старый длинный список по умолчанию.

| Задача | Поле / действие | Результат |
| --- | --- | --- |
| Создать папку | Имя папки / Создать | Новая папка в захваченном месте, фокус и выделение на созданном объекте |
| Создать файл | Имя файла / Создать | Пустой файл; это не запуск редактора и не создание документа из шаблона |
| Выделить по маске | Маска имён / Выделить | Совпавшие имена добавляются к текущему выбору |
| Снять по маске | Маска имён / Снять выделение | С совпавших имён снимается выбор; остальной выбор сохраняется |
| Комментарий | Текущее значение / Сохранить | Меняется свойство конкретного сфокусированного объекта, если provider поддерживает его |

При открытии поле получает фокус и выделение текста. Enter применяет команду,
Escape/«Отмена» сохраняет исходный список и возвращает фокус. Смена раздела,
панели или другого окна не должна подменять захваченное место и объект.

## Имена и создание

Пустое имя не запускает операцию. Полное введённое значение сохраняется без
молчаливого trim/исправления. Проверки конкретного пути, ограничений платформы,
состояния источника и конфликтов выполняются существующим native владельцем.
В частности, сохраняем CorrectFsPath/IsCorrectFsName и защиту от embedded NUL,
а не вводим собственный универсальный список запрещённых символов для всех ОС.

При существующем имени или отказе ввода форма сохраняет значение, показывает
причину и позволяет исправить его. Ошибка доступа сама по себе не должна
навсегда блокировать повтор: права могли измениться вне приложения. Известный
read-only источник, напротив, не разрешает запись ни кнопкой, ни Enter.
Отмена не создаёт объект. После подтверждённого успеха список перечитывается,
сохраняет порядок сортировки и выделяет созданное имя по native правилам.

Вложенные/абсолютные пути не переопределяем по возможностям HTML-примера.
Сохраняется текущий native разбор, создание родительских папок и определение
фокусируемого элемента. В макете простое имя добавляет демонстрационную строку;
сложный путь показывает операцию, без реального обхода/создания каталогов.

## Выделение

Маски находятся в «Правке», отдельно от файловых изменений. Источник только
для чтения не запрещает менять выделение. * и ? объясняются коротко рядом с
полем; окончательное сопоставление выполняет DoesWildcardMatchName, с правилами
регистра текущего native владельца. Не заменяем его regex-парсером приложения.

Совпадения могут включать папки. Нулевой результат не ошибка файловой операции:
выбор не меняется, пользователь получает короткий статус. Снятие по маске не
сбрасывает остальные выбранные объекты. В HTML есть ограниченная иллюстрация
*/? на демонстрационных строках; она не является эталоном Unicode/case-поведения
native matcher и не переносится в C++.

«Правка» также использует действующие команды Вырезать/Копировать/Вставить,
Выделить всё/Снять/Инвертировать. Доступность clipboard-команд берётся из той
же модели, что панель действий. Меню и файловый context popup используют одну
поверхность с общими размещением, клавиатурой, закрытием и возвратом фокуса.

## Комментарий

Показываем имя конкретного объекта и текущее свойство; место — в подсказке
SourceSummary. Пустое значение
разрешено: оно очищает комментарий. Отмена оставляет прежнее значение.
Команда не является массовым изменением всего выделения. Доступность зависит
от provider/CanComment, а не от догадки по расширению файла. Не обещаем запись
комментария в любой архив или файловую систему.

Сохраняем существующий однострочный контракт CComboDialog; многострочный редактор
не добавлен без проверки формата хранения. Ошибка записи не маскируется
успешным закрытием. Дальнейшее обновление списка и свойства выполняет native
owner. HTML хранит только демонстрационное свойство текущей модели и показывает
его в «Свойствах»; реальный файл, архив или метаданные не изменяются.

## Основания и приёмка реализации

Просмотрены CreateFolder/CreateFile/OnEndLabelEdit в
[PanelNameOperations](../../../src/filemanager/panels/PanelNameOperations.cpp),
CanComment/ChangeComment в [PanelOperations](../../../src/filemanager/panels/PanelOperations.cpp),
SelectSpec в [PanelSelect](../../../src/filemanager/panels/PanelSelect.cpp),
matcher в [Wildcard](../../../src/fileops/patterns/Wildcard.cpp) и полный контракт
ввода/BindLanguage в [ComboDialog](https://github.com/Feverqwe/7zip-qt-port/blob/ed197ad23afd33abf073e9fae1bb6fa113640e43/src/dialogs/combo/ComboDialog.cpp).
Native сборщики, команды и алгоритмы не менялись.

В браузере проверены создание с Unicode и пробелами, фокус/выделение результата,
повтор существующего имени без потери ввода, additive selection/deselect,
закрытие «Правки» с возвратом фокуса, комментарий с HTML-символами, повторное
открытие и пустое значение для очистки. Ошибки и длинное имя помещаются в
компактную форму. Реальная обработка ошибок записи, native сортировка/обновление,
жизненный цикл provider и все платформенные ограничения требуют Qt-проверки.

Будущие проверки защищают результат: Cancel без изменения, пустой и NUL-ввод,
конфликт имени, readonly, изменение/исчезновение источника, Unicode/пробелы,
сложный путь по native правилам, точный результат matcher, отсутствие потери
другого выделения, комментарий/очистка/ошибка записи. Само наличие поля или
текста метода не является проверкой сценария.
