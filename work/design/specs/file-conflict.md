# Конфликт файлов

Статус: пользователь согласовал три действия, общий флажок и показанный диалог
4 ноября 2026, после чего выбрал переход к ходу операции. Qt-реализация не изменена.
Это часть [копирования и перемещения](copy-move.md), также применимая к распаковке.

## Согласованное решение

Вместо шести отдельных кнопок — «Заменить», «Пропустить», «Сохранить оба»
и флажок «Применить к остальным конфликтам этой операции».
По умолчанию флажок выключен: выбор действует на текущий конфликт.
«Отменить операцию» — отдельное действие, не разновидность пропуска.

| Действие | Текущий конфликт | При включённом флажке |
| --- | --- | --- |
| Заменить | Записать входящий файл вместо существующего | Заменять следующие конфликтующие файлы этой операции |
| Пропустить | Не записывать входящий файл, существующий оставить | Пропускать следующие конфликты этой операции |
| Сохранить оба | Существующий оставить, входящему подобрать свободное имя | Так же обрабатывать следующие конфликты этой операции |
| Отменить операцию | Передать отмену владельцу операции | Флажок не учитывается |

Правило не затрагивает другие операции, окна или следующий запуск и не меняет
глобальные настройки. Пропуск при перемещении не разрешает удалить пропущенный
источник. «Сохранить оба» не означает предварительное переименование источника.
Подбор свободного имени принадлежит существующей файловой/архивной операции.
Предлагаемый суффикс не обещается заранее: имя может стать занятым до записи.

## Компоновка и данные

Заголовок «Файл уже существует» и имя конфликтующего файла. Затем две области:
«В назначении» и «Входящий файл». В каждой — имя, размер и время изменения;
полное место файла доступно в подсказке общего SourceSummary.
Входящий объект не называется «файлом из архива», если источник — обычная папка.
Неизвестные размер и время обозначаются явно. Одинаковые размер и дата сами
по себе не означают одинаковое содержимое; диалог не обещает сравнение хешей.

Далее краткое пояснение «Сохранить оба», флажок и три равноправные кнопки.
При заведомо единственном конфликте флажок не нужен. Число выбранных корневых
папок не доказывает, что внутри будет лишь один конфликт.
При узком окне области сравнения и действия становятся вертикальными.
Длинные строки переносятся; нижние кнопки доступны прокруткой формы.

Предложение по клавиатуре: фокус на «Пропустить», Enter активирует выбранную
кнопку; Tab проходит доступные элементы. Escape и закрытие диалога означают
отмену операции. Замена не запускается одним открытием окна или сменой флажка.
Возвращаться в главное окно как будто операция успешно закончилась нельзя.

## Папки и ограничения

Этот диалог относится к конфликту двух файлов. Не вводим общий вопрос
«объединить папки»: в проверенном файловом маршруте две папки объединяются,
а конфликты вложенных файлов запрашиваются отдельно. При несовместимых типах
«файл / папка» существующие маршруты возвращают диагностическую ошибку;
макет не обещает замену дерева, пропуск или объединение поверх этой ошибки.
Ссылки, streams и архивные маршруты сохраняют свои проверки и ограничения.

Если вызывающий сценарий запрещает пакетные решения, флажок скрывается.
Если маршрут не поддерживает отдельное действие, оно не имитируется успешным.
Специальный вызов из внешнего редактирования должен сохранить свой контракт
ограниченных ответов; его не следует автоматически расширять по этому макету.

## Граница реализации

Проверены текущие владельцы: [диалог](../../../src/dialogs/overwrite/OverwriteDialog.cpp),
[представление](../../../src/dialogs/overwrite/qtoverwritepresentation.cpp),
[снимок вопроса](../../../src/fileops/overwrite/overwritequestion.h),
[файловая операция](../../../src/fileops/transfer/qtfiletransfertransaction.cpp),
[callback файлового менеджера](../../../src/filemanager/ExtractCallbackOutput.cpp),
[callback распаковки](../../../src/archive/callbacks/ArchiveExtractCallback.cpp).
Оригинальные тела и ресурсы сверены с закреплённым
[baseline](../../../docs/ui-reference/overwrite-dialog.reference.json).
Действующий UI-контракт находится в [extraction](../../../docs/ui-layout-contracts/extraction.md).

Replace/Skip для одного и всех уже имеют отдельные ответы. Существующий
Auto Rename устанавливает режим для последующих конфликтов. Согласованный
«Сохранить оба» для одного файла потребует отдельного типизированного решения
на границе UI/операции и обработки во всех затронутых потребителях. Нельзя
выдать нынешний Auto Rename при выключенном флажке: это молча изменит область
решения. Используем существующий алгоритм свободного имени, не пишем новый.
Пакетное решение хранится у операции, вне виджетов и общих настроек.

Отмена не обещает общего отката всех маршрутов: уже опубликованные изменения
и частичный результат показывает владелец операции. Будущий итог должен
различать отмену, пропуски, ошибки и успех; этот экран результата ещё не принят.

## Проверки

- Каждое из трёх решений отдельно и с флажком: текущий/следующий конфликт,
  отсутствие влияния на параллельную и новую операцию.
- При «Сохранить оба» существующие байты сохраняются, входящий получает
  свободное имя; повторное столкновение при подборе имени не перезаписывает файл.
- При Move + Skip пропущенный источник сохранён; Cancel прекращает ожидание
  ответа и не сообщает полный успех. Проверяется фактический результат маршрута.
- Один конфликт, неизвестные метаданные, длинные Unicode-имена, компактная форма,
  Tab/Enter/Escape, закрытие окна и запрет пакетных решений.

В браузерном макете показаны решения и их область на демонстрационных данных.
Кнопка «Смоделировать конфликт» вне продукта позволяет пройти следующий запрос:
при выбранном правиле он обрабатывается без повторного диалога. Файлы не меняются.
