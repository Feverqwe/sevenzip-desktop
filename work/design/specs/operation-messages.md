# Сообщения и текстовые отчёты

Актуализация макета v96. Сообщения и длинный отчёт видны сразу в окне операции. Длинный вывод прокручивается внутри отчёта. Описания ранних вариантов ниже приведены для справки.
Описания прежних поверхностей ниже сохранены для справки. См. [план интерфейса](implementation-scope.md).

Статус: проработано автономно по поручению пользователя 5 ноября 2026, v36.
[Сообщения](../index.html?review=reports-v36#messages),
[полный текст](../index.html?review=reports-v36#text).

Результат операции показывает короткое итоговое сообщение. Если есть проблемы,
можно раскрыть их в окне операции; для длинного вывода используется отдельное
окно сообщений. Каждое сообщение показывает причину и имя файла. Известный
полный путь доступен при наведении на SourceSummary и сохраняется при копировании
отчёта. Убираем столбец порядковых номеров и строку счётчиков.
Порядок сообщений сохраняется. Ошибки, предупреждения и частичный результат
не объединяются в безусловное «Готово».

«Копировать» копирует итог и весь
отчёт, включая текст за пределами видимой области. В пустом результате кнопка
недоступна и не затирает буфер. «Закрыть»/Escape закрывает только отчёт;
операция и её результат имеют собственного владельца. Просмотр не повторяет
операцию и не удаляет сообщения. В обычном и компактном размерах список
прокручивается, действия остаются доступны.

Полный текст нужен для передачи диагностики и лицензий. Это read-only область
с поиском/выделением штатными средствами и полным копированием, без имитации
консольного клиента. Не добавляем автоматически итоговую статистику из старого
шаблона. В текстовом отчёте сохраняется исходная диагностика, а не только её
короткий пересказ. Лицензия остаётся отдельным документом с точным текстом.

Прочитаны CMessagesDialog::AddMessage/OnInit/Create и существующий ListView
clipboard. Текущий native транспорт может давать непрерывный диагностический
текст. Если путь/тип известен типизированно, используем отдельные поля. Если
доступна лишь строка, показываем её целиком; не делим по двоеточию, слешу или
локализованным словам. Источник, порядок и полнота сообщений сохраняются.

HTML показывает фиксированные сообщения и длинный/пустой пример. Будущие
проверки: многострочная диагностика, неизвестный тип, путь с Unicode и
двоеточием, длинный вывод, смешанные результаты, полный clipboard, пустой
отчёт, закрытие отчёта без потери операции. Runtime Qt ещё не изменён.
