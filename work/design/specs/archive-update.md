# Обновление существующего архива

Статус: автономная проработка после разрешения продолжать без подтверждений,
5 ноября 2026. Макет — раздел «Создание и обновление архива», состояния занятого
имени, обновления 7z/ZIP, зашифрованного архива и синхронизации. Это контракт
предлагаемого интерфейса; текущий Qt ещё не обеспечивает весь описанный маршрут.

## Занятое назначение

После подтверждения создания проверяем назначение официальным владельцем
архивной операции. Существующий файл не превращает намерение «Создать» в Update
без решения пользователя. Пока идёт проверка, повторный запуск недоступен;
отмена возвращает форму с её значениями.

Для распознанного изменяемого архива: «Архив уже существует», полное назначение,
«Отмена», «Добавить в архив…», «Изменить имя». Начальный фокус — изменение имени.
Escape отменяет решение и возвращает исходную форму; ни одна кнопка здесь
не запускает обновление. «Изменить имя» выделяет имя в прежней форме.
«Добавить…» переводит её в форму «Обновить архив».

Для обычного файла, каталога, недоступного или неизменяемого архива предлагаем
другое имя/папку и конкретную причину. Автоматической замены физического файла,
удаления старого архива или обхода ограниченного чтения нет. Если открытие для
проверки требует пароль, используем существующий запрос пароля; Cancel сохраняет
форму, ошибочный пароль не доказывает, что файл не является архивом.

HTML не проверяет диск. Внешний переключатель «Состояние» задаёт результат
проверки на примере; после изменения имени/папки пример считается свободным.
Для реального приложения это не правило определения существования.

## Форма обновления

Вместо редактируемых имени, папки и формата — карточка выбранного архива с полным
местом. Тип берём из открытого reader, а не расширения. Выделение исходников
захватываем до открытия формы; его путь и имена доступны в раскрытии.
Смена активной вкладки/другого окна не подменяет ни архив, ни источники.

Основное поле — «Действие». Начальный выбор «Добавить и заменить» соответствует
существующему Add; свёрнутые технические настройки не прячут этот выбор.

| Действие | Результат |
| --- | --- |
| Добавить и заменить | Добавить новые имена; совпадающие заменить независимо от даты |
| Добавить новые и более свежие | Добавить новые; совпадающие обновить по сравнению движка, более свежие записи архива сохранить |
| Обновить только существующие | Обновить совпадающие по сравнению движка, новые имена не добавлять |
| Синхронизировать | Добавить новые, обновить по сравнению движка и удалить отсутствующие записи внутри выбранной области |

«Более свежие» — краткое объяснение, не новый алгоритм UI. Если native не может
определить новизну, действуют его правила; одинаковое время не означает равенство
байтов. Сравнение времён, точность, неизвестные значения, маски и пары путей
остаются в существующем Update. Форма не вычисляет независимый diff.

При синхронизации рядом видны последствия и отдельный непредвыбранный флажок
«Удалить записи архива, отсутствующие в выбранных источниках». Без него запуск
недоступен, в том числе по Enter. Речь об области native censor: записи вне неё
сохраняются. UI не расширяет её до всего архива. Новая цель/новый вызов сбрасывает
подтверждение; сохранённый профиль не разрешает удаление в следующей операции.

Кнопки: «Отмена», «Обновить архив». «Создать другой архив…» возвращает обычную
форму с новым предложенным именем; это создание из выбранных исходников,
а не копия, конвертация или Save As всего старого архива.

Уровень, экспертные свойства и их отдельный Apply/Cancel переиспользуются из
[создания](create-archive.md). Они относятся к обрабатываемым записям; не обещаем
пересжать скопированные записи. Разделение существующего архива на новые тома
здесь недоступно. Неподдерживаемые SFX/многотомные/составные входы отклоняет
их native владелец с причиной, а не фильтр расширений интерфейса.

## Пароль и защита

В форме обновления нет управления сменой пароля всего архива. Неизменённые
записи могут переноситься движком без повторного шифрования, поэтому такая
кнопка давала бы ложное обещание. Для зашифрованного входа показываем, что новые
и заменяемые файлы также должны получить защиту, и при необходимости будет
запрошен пароль. Пароль открытия и пароль записи принадлежат операции; совпадение
их значений само по себе не является доказательством совместимости.

Реализация должна передавать проверенный контекст шифрования через typed native
границу: методы/шифрование имён, выходной пароль и необходимость запроса. При
невозможности сохранить требуемую защиту запуск останавливается с причиной;
создание незашифрованных новых записей как запасной вариант запрещено.
Для смешанного архива нельзя выдумывать единый метод по первому файлу: native
определяет возможности, а необходимый выбор требует отдельного явного решения.
Это доработка адаптера, не уже проверенная возможность нового интерфейса.
HTML не хранит пароль в модели операции и не проверяет шифрование.

## Операция, ошибки и повтор

Подтверждение захватывает архив, исходники, режим и подтверждение удаления;
открывается самостоятельное окно «Обновление архива». Главное окно остаётся
доступным. Совпадения имён обрабатываются выбранным Update action set, поэтому
диалог Replace/Skip/Keep Both из копирования для каждой записи здесь не появляется.
Пароль, ошибки чтения/записи, остановка и результат используют общие компоненты.

Успех закрывается автоматически с кратким статусом в операциях. Ошибка или
отмена остаётся видимой; временный вывод не выдаётся за готовый архив.
Не обещаем атомарность всех поддерживаемых форматов/носителей: действующий
владелец публикации и восстановления определяет фактический результат.
Повторный запуск снова проверяет назначение, доступность и конфликт записи.

Особенно важна гонка между проверкой формы и началом записи. Создание должно
нести намерение «новый отсутствующий файл», обновление — конкретный выбранный
архив/его идентичность. Под существующим write lease native повторно проверяет
это условие. Появление другого файла или замена архива требует нового решения,
не молчаливого Add. Названия DTO свободны; отдельный intent и проверка на границе
записи — требование поведения, а не обязанность ввести определённый класс.

Оригинальные полные UpdateAction.cpp/.h и ресурс CompressDialog прочитаны из

Поверхности собираются из SourceSummary, Disclosure, Field, InlineMessage,
DialogSurface и ActionBar. Решение о занятой цели использует общую модальную
поверхность с собственными действиями, Escape и возвратом фокуса; Qt берёт
контекстную модальность из существующего слоя диалогов. Содержимое скроллится,
действия остаются видимыми, включая 480×640 и длинные имена.

Будущая native-проверка: свободное/занятое имя и гонка появления файла; формат
по reader; Cancel после проверки/пароля; более новая/старая/равная/неизвестная
дата; новое имя в Add/Update/Fresh; Sync внутри маски и сохранение вне неё;
непредвыбранное разрешение удаления; шифрование добавляемых/заменяемых записей;
read-only/многотомный/SFX/неподдержанный update; write lease между двумя окнами;
success/error/cancel и фактическое состояние исходного/выходного архива.
HTML-проверки этих переходов не заменяют native-проверку содержимого.
