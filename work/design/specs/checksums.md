# Контрольные суммы

Статус: проработано автономно по поручению пользователя 5 ноября 2026, v35.
[Макет результата](../index.html?review=checksums-v35#hash). Расчёт в HTML
демонстрационный, нативный код не изменён.

## Запуск и результат

Алгоритм выбирается в меню «Контрольные суммы» для выделенных файлов или папок.
Отдельная предварительная форма не нужна. Доступны алгоритмы установленного
движка; конкретный набор и работоспособность определяет его каталог. «Все
алгоритмы» означает доступные методы, а не повторные независимые обходы файлов.

Операция использует отдельное окно и остаётся в списке операций. Доступны
сворачивание, продолжение навигации и остановка; нет назначения для записи,
счётчиков скорости/времени и конфликтов перезаписи. Для записей зашифрованного
архива используется согласованный запрос пароля. Чтение внутри архива остаётся
потоковым через существующий native маршрут, без нового console subprocess.

После расчёта результат остаётся открытым: именно значения являются результатом
этой операции. Это уточнение общего правила автозакрытия успешных операций.
Показываем алгоритм, источник и строки по файлам. Каждое значение можно выделить
или скопировать отдельной кнопкой; она копирует только само значение. «Копировать
все» включает алгоритмы, имена и полные значения, а также сообщения проблем.
Ни переносящийся хеш, ни длинный путь не обрезаются при копировании.

«Расчёт завершён» не означает совпадения с ожидаемой суммой и не является
вердиктом о происхождении/целостности архива. После ошибки соответствующая строка
показывает причину, без правдоподобного частичного digest. При отмене сохраняются
только завершённые результаты; остальные отмечаются как незавершённые. Ошибка
отдельного файла не скрывает удачные результаты других.

Старые неподключённые команды раньше открывали один фиктивный результат и были
убраны в v35. В v43 вместо них добавлены отдельные
[создание и проверка checksum-файлов](checksum-files.md), с формами, назначением,
native writer/reader и различающимся результатом. Это реализуемый контракт
макета, не утверждение, что новые Qt-маршруты уже написаны. Проверка использует
существующий native provider, а не сравнение текстовых строк в представлении.

## Что требуется от реализации

Просмотрены CApp::CalculateCrc2, полный filesystem worker CalculateFileCrc,
HashGUI/AddHashBundleRes, типы HashCalc и потоковый вызов PanelCopy, а также
оригинальные CalculateCrc2/AddHashBundleRes из локального исходного архива.
Native алгоритмы и формат digest сохраняются. Существующий итог нескольких
файлов — суммарные группы DataSum/NamesSum/StreamsSum. Его нельзя подписывать
SHA-256 одного файла или выдавать за стандартный checksum manifest.

Новый построчный результат требует доработки сборщика результатов. Снимок
завершённого digest нужно брать у текущего native hasher после успешного
завершения файла, вместе с идентичностью записи и статусом. Для filesystem
worker — после успешного Final; для общих/архивных callbacks — на их границе
завершения. Не переписываем чтение, перечисление, digest или правила ошибок
ради нового списка. Пер-file значения не восстанавливаются из суммарного digest.

Суммарные native группы сохраняются в дополнительной технической сводке, если
они нужны текущим потребителям; базовый список остаётся пофайловым. HTML пока
не моделирует эту сводку и не доказывает её подключение. Нужна типизированная
модель для полного/частичного/отменённого результата, независимая от закрытия
файлового окна. Успешное чтение и проверка native stream должны предшествовать
публикации значения; ошибка не оставляет действительный на вид digest.

В HTML фиксированные значения и служебные состояния над продуктом. Для выбранной
папки используется пример вложенного файла, без настоящего обхода файловой
системы. В реализации имена и объём приходят из родного enumerator; симлинки,
flat mode, потоки, вложенные архивы и cancellation сохраняют его контракт.

Проверки будущей реализации: известный digest для файла Unicode/пробелы,
несколько файлов с разными значениями, папка/пустой файл, архивная запись,
ошибка чтения, отмена во время чтения, отсутствие digest для незавершённого,
копирование одного/всех без усечения, смена исходного выбора и независимые
операции. Геометрия и runtime проверяются отдельно от переноса алгоритма.

## Рамка макета

По замечанию пользователя устранено уменьшение всей оконной рамки при переходе
к свойствам, отчётам, настройкам и About. Размер рабочей области зависит от
доступного места, а ширина самой формы ограничивается внутри. Это поведение
страницы просмотра, не требование делать настоящее окно About полноэкранным.
Самостоятельные операции сохраняют собственное компактное окно.
