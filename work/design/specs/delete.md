# Удаление

Статус: проработано автономно по поручению пользователя 5 ноября 2026, v39.
[Макет](../index.html?review=delete-v39#delete). Нативное приложение не изменено;
демонстрационная операция не удаляет реальные или тестовые файлы.

## Состав и действия

Используются общие DialogSurface, SourceSummary, Disclosure, InlineMessage и
ActionBar из [компонентной системы](design-system.md). Показываем выбранный
объект или число объектов и исходное место. Для нескольких объектов имена
раскрываются отдельно. Не выводим выдуманный общий размер и не подставляем
фиксированные четыре файла из старого шаблона. Последствия находятся перед
необязательным раскрытием списка.

| Сценарий | Заголовок / действие | Пояснение |
| --- | --- | --- |
| Обычные файлы | Переместить в Корзину? / В Корзину | Объекты можно восстановить из Корзины после успешного перемещения |
| Явное постоянное удаление | Удалить безвозвратно? / Удалить безвозвратно | Корзина не позволит восстановить эти объекты |
| Записи архива | Удалить из архива? / Удалить из архива | Изменяется архив, записи не попадают в Корзину |

Для папок отдельно указываем, что удаляется содержимое. Источник только для
чтения не разрешает подтверждение. Текст и имена переносятся; содержимое
прокручивается, нижние действия остаются доступны. Начальный фокус на «Отмена».
Enter на отмене не запускает удаление, Escape возвращает к исходному списку
с сохранённым выделением. Разрушительное действие должно быть выбрано явно;
оно не становится default только из-за частоты использования.

В macOS обычный запуск — ⌘Backspace, явное постоянное удаление — ⇧⌘Backspace;
при редактировании текста они не перехватываются файловой командой. Windows/
Linux используют соответствующие штатные команды и сочетания. Обычная кнопка
«Удалить» не запоминает, что предыдущая команда была безвозвратной.

## Операция и результат

Подтверждение захватывает конкретное исходное место и выбранные записи.
Дальнейшая смена выделения не меняет выполняемую операцию. Ход работы использует
общее отдельное окно: источник, файл/прогресс, остановка, сообщения. Поля
назначения и конфликта перезаписи здесь нет. Для удаления из зашифрованного
архива сохраняется возможность native запроса пароля в области операции.

После частичного отказа показываем конкретные проблемы и перечитываем источник.
Не удаляем строки из модели заранее и не обещаем откат уже выполненных
изменений. Для архивов публикацию нового состояния определяет существующая
операция обновления, а не закрытие прогресса. При отмене подтверждения операция
вообще не создаётся.

Если система не смогла переместить файл в Корзину, не превращаем эту команду
в постоянное удаление. Ошибка остаётся ошибкой; безвозвратное удаление возможно
только как отдельное явное действие. В частности, сохраняем конкретные
ограничения native Trash service, а не обходим их новой UI-эвристикой.

## Основания для реализации

Просмотрены полные текущие ConfirmDeleteItems/MoveItemsToTrash/DeleteItems в
[PanelOperations](../../../src/filemanager/panels/PanelOperations.cpp),
[Trash boundary](../../../src/platform/trash/qttrashservice.h) и оригинальный
CPanel::DeleteItems из локального source archive. Upstream разделяет shell
Recycle Bin для filesystem и внутреннюю операцию удаления; текущий порт
использует Qt/native trash и сохранённую внутреннюю операцию.

Новая форма меняет представление и default с исходного Yes на явное Cancel;
названия действий заменяют неоднозначные Yes/No/Cancel. Сохраняем native
выбор индексов, CheckBeforeUpdate, read-only guards, worker, cancellation и
публикацию/обновление списка. Не реализуем удаление архивных записей через
ручное изменение файлов или консольный subprocess.

HTML проверен на фактическом одиночном/множественном выборе, обычном и
постоянном запуске, отмене с сохранением выбора, удалении из архива, недоступном
подтверждении для read-only и длинных именах в компактном окне. Начало операции
в макете демонстрирует владение контекстом, а не реальный результат файловой
системы. Native Windows визуальный reference этой новой формы не принимался.

Будущая проверка: успех/частичная ошибка/отмена, отказ Trash без fallback,
папки и ссылки по фактическим возможностям source owner, Unicode/пробелы,
удаление архивной записи и обновление всех представлений, read-only источник,
изменившийся/исчезнувший объект, default/фокус/клавиатура и длинный список.
