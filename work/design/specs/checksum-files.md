# Файлы контрольных сумм

Статус: автономная проработка, 5 ноября 2026. В макете добавлены отдельные
маршруты создания, проверки и результата; они используют native `Hash` как
основание для реализации. HTML не читает файлы и не рассчитывает суммы.

## Три разных действия

Меню «Контрольные суммы» сохраняет расчёт выбранного алгоритма и всех алгоритмов
с [пофайловым результатом](checksums.md). Дополнительно доступны «Создать файл
сумм…» и «Проверить файл сумм…». Это отдельные операции, а не экспорт любого
отображаемого текста и не один фиктивный общий экран.

Создание берёт захваченный выбор активной панели. Папка — источник рекурсивного
обхода, не файл с искусственно рассчитанной суммой имени. Native enumerator
определяет состав, пути, потоки и порядок. Дальнейшая смена выбора или вкладки
не меняет запрос. Если нет допустимых источников, действие недоступно.

Проверка получает готовый manifest. Для выбранного распознанного checksum-файла
предзаполняем его и папку; иначе используем системный выбор файла. Пример
SHA256SUMS в HTML имеет известный демонстрационный тип; определение реального
формата принадлежит reader, не проверке имени в кнопке.

## Создание

Небольшая форма: источник и раскрываемый список объектов, алгоритм, имя файла,
папка назначения. «Выбрать…» использует системную панель папки. В макете вместо
неё ввод демонстрационного пути; Cancel сохраняет форму и возвращает фокус.
Кнопки «Отмена», «Создать файл». Enter подчиняется обычному контракту формы.

Алгоритмы и допустимые параметры приходят из доступного native каталога.
Начальное значение — действующий профиль; SHA-256 и SHA256SUMS в макете являются
примером, не новым фиксированным каталогом и не запретом других имён. При смене
алгоритма автоматически предложенное имя меняется, пользовательское сохраняется.
Нет сжатия, пароля для выходного списка, размера словаря или разделения на тома.
Если исходные записи зашифрованы, пароль чтения запрашивает их операция.

Имена в списке относительные, с сохранением структуры источника. Native writer
отвечает за формат строк, UTF-8, экранирование, разделители и особенности метода.
Файл содержит значения отдельных файлов, а не суммарные DataSum/NamesSum.
Сам файл результата и служебный временный вывод не должны попадать в обход.
Если пользователь явно выбрал файл, совпадающий с назначением, нужно другое имя;
не исключаем единственный исходник незаметно. Несколько корней/виртуальные
источники требуют существующего native отображения путей, не простого basename.

Папка, относительно которой записаны имена, — контекст источников. Если список
сохранён в другом месте, при проверке нужно выбрать эту папку; её нельзя молча
подменить местом сохранения. Для архивных записей имена относятся к структуре
выбранных записей; такой manifest не обещает автоматически проверять их будущие
переименованные/плоско извлечённые копии.

Занятое имя открывает явное решение: «Отмена», «Изменить имя», «Заменить».
Начальный фокус — Cancel. Замена создаёт полный новый список, не дописывает
строки к старому и не запускает режим обновления архивных данных. Повторная
проверка цели перед публикацией должна сохранить это намерение при гонке.

Расчёт и запись идут отдельной операцией, без статистической таблицы и времени.
Непрочитанный/пропущенный/незавершённый исходник не получает строку с правдоподобной
пустой суммой. Выход готовится через существующего владельца записи; успешная
публикация разрешена только после проверки полного результата. При ошибке/
отмене итог не выдаётся за готовый manifest, прежний файл не считается заменённым.
Если фактический отказ публикации оставил иной результат, показываем его честно.
Чистый успех закрывает окно операции с кратким статусом и полным назначением.

## Проверка по списку

Форма: «Файл сумм», «Папка с файлами», системный выбор для каждого поля,
«Отмена», «Проверить». По умолчанию база — обычная папка manifest, но её можно
изменить, например для отдельно скачанного списка. Подпись прямо объясняет,
откуда отсчитываются имена. Алгоритмы определяет native reader по содержимому/
поддерживаемому формату, без ручного выбора, способного исказить смысл списка.

Список внутри архива требует подготовки через официальный reader и явной
обычной папки проверяемых файлов. Каталог временного извлечения не становится
базой проверки автоматически. Это требует адаптера базового пути и контекста
источника; наличие reader не доказывает уже готовый маршрут в новом интерфейсе.
Пароль относится к чтению источника, не к checksum-тексту.

Проверка идёт отдельной операцией чтения. Она не извлекает проверяемые файлы
поверх источников, не исправляет содержимое, не запускает внешние утилиты.
Неподдерживаемый алгоритм/формат, некорректная запись, отсутствующий файл,
ошибка чтения и несовпадение суммы — разные результаты. Пути вне выбранной
базы, абсолютные пути и небезопасные переходы/ссылки не разрешают произвольное
чтение: сохраняем действующую native валидацию, повторяя её для выбранной базы.
UI не «чинит» опасный путь в другое имя и не утверждает, что проверил исходную
запись. Строка результата показывает причину отказа.

## Результат

Успешная проверка оставляет результат открытым: «Файлы соответствуют списку».
Для каждого элемента — полное имя и состояние. При несовпадении раскрываются
ожидаемое/полученное значение и метод, только если native действительно передал
их. Неизвестное значение не заменяется нулём или повтором ожидаемой суммы.

Ошибки не скрывают удачные строки, а отмена сохраняет завершённые результаты
и явно показывает незавершённые. Пустой список сообщает, что проверять нечего;
он не является зелёной проверкой нуля файлов. Некорректный список показывает
ошибку чтения формата. Общий успех требует завершения всех запрошенных проверок,
отсутствия несовпадений/пропусков/ошибок и непустого проверенного набора.

«Копировать отчёт» включает manifest, базу, имена, состояния и доступные полные
значения. «Закрыть» закрывает результат, сохраняя запись операции по общему
контракту. Длинные данные прокручиваются внутри поверхности; действия видны.
Результат чтения не является обещанием происхождения manifest или автора файлов.

[действующая валидация путей](../../../src/archive/backend/archivebackend_hash.cpp).

Важные границы реализации:

- Writer уже есть в CHandler::UpdateItems, со штатными SetProperties/WriteLine.
  Закомментированный HashFilePath в общем HashCalc worker не является готовым
  способом создать файл. Не раскомментируем старую ветку и не пишем свой serializer
  из экранного/суммарного отчёта. Запрос идёт через ArchiveBackend и native writer.
- Native reader выполняет сравнение в CHandler::Extract и передаёт результат
  по каждой записи через callback. HRESULT S_OK сам по себе не означает совпадения:
  CRC error/unsupported method и ошибки открытия нужно собрать отдельно.
  При отсутствующем stream запись может не дойти до обычного SetOperationResult;
  сборщик обязан сохранить её ошибку, а не потерять строку результата.
- Writer может получать S_FALSE при отказе выдать stream. Успешный выход writer
  не заменяет проверку ошибок/пропусков его callback. Публикация manifest после
  такого отказа запрещена контрактом полного результата; не допускаем выдачу
  строки пустого файла вместо непрочитанного источника.
- Нужны typed DTO источников/manifest/base/output intent и пофайлового результата,
  применение выбранной базы к reader вместе с общей path validation и публикация
  результата у владельца операции. Снимки expected/actual берутся у native hasher
  на завершении, не рассчитываются повторно в представлении.

Полные тела UpdateItems и Extract сравнены с оригиналами локального source.tar.xz
по лексическим токенам без комментариев/форматирования: отличия — scoped external
hash codecs и передача этого контекста в AddDefaultMethod. Это свидетельство
источникового сравнения, не runtime-проверка и не верификация всего baseline.
Нового импорта исходников и C++ изменений в этой дизайн-итерации нет.

Компоненты: SourceSummary, Disclosure, Field/SystemPathField, ActionBar,
контекстная поверхность решения, OperationSurface и общий FileOutcome result.
Та же функция результата используется в каталоге состояний и завершённой
операции. Коллектор данных и файловое IO остаются за своими модулями.

Будущая проверка реализации: native-generated список и повторная проверка;
несколько файлов/папка/пустой файл; Unicode, пробелы и экранируемые имена;
изменённая база; запрещённые пути и ссылки; unknown/malformed/empty manifest;
match/mismatch/missing/read-error/cancel; ожидаемое и фактическое значения;
ошибка источника не публикует список; замена и гонка цели; выбор места/Cancel;
зашифрованный источник; независимость от выбора, вкладки и закрытия окна.
