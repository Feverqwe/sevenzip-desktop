# Свойства файлов и выбранных объектов

Статус: показанный макет v34 согласован пользователем 5 ноября 2026.
Qt-приложение не изменено.
[Открыть макет](../index.html?review=properties-v34#properties).

## Представление

Компактное окно сведений: имя и тип объекта, расположение, размер и известная
дата изменения. Значения доступны для выделения и копирования. Технические
свойства, комментарии и сведения о внешнем архиве видны сразу. В
свойствах не запускаются проверка архива, вычисление хеша или распаковка.

Внизу доступно «Копировать сведения». Окно закрывается крестиком в заголовке.
Копирование включает
полные значения технических сведений. Обычное
выделение текста позволяет скопировать нужный фрагмент. Escape закрывает окно;
после закрытия фокус возвращается к исходному списку. Имя и длинный путь
переносятся, содержимое прокручивается, действия остаются видимыми.

Это информационная форма. Здесь нет нового редактора прав доступа, владельца,
времени или атрибутов. Переименование остаётся действием файлового списка.
Модель будущего окна должна удерживать выбранные объекты при последующей
навигации: новое выделение не должно незаметно менять уже открытые сведения.
HTML показывает переход между представлениями; отдельное немодальное
Qt-окно с одновременной навигацией ещё не реализовано и не проверено.

## Состояния и достоверность

| Источник | Представление |
| --- | --- |
| Обычный файл | Фактически доступные размер, дата, расположение и дополнительные свойства |
| Папка | Размер содержимого не подсчитан; ноль не подставляется вместо отсутствующих сведений |
| Файл внутри архива | Свойства выбранного файла; внешний архив назван отдельно |
| Несколько объектов | Число выбранных файлов/папок и видимый список имён; нет общей даты одного случайного файла |
| Неполные данные | Понятное обозначение недоступного основного значения; неизвестные технические поля не выдумываются |
| Длинные значения | Полное значение с переносом и прокруткой, копирование без усечения |

Сохранённая в архиве CRC помечается как значение из метаданных, без утверждения
о проверке содержимого. SHA-256 не появляется автоматически. Упакованный размер
одной записи, размер контейнера и размер данных не взаимозаменяемы. Особенно
важно не выдавать размер solid-блока за точный упакованный размер файла.

Для множественного выбора итоговый размер показывается только при достаточных
данных. Если вычислена лишь часть, это подписывается как часть, а не полный
размер. Макет консервативно показывает «Не подсчитан»; новую фоновую рекурсивную
оценку с отдельной кнопкой в этом предложении не вводим.

## Открытие и владельцы

«Свойства» доступны из меню «Файл», контекстного меню и по ⌘I в macOS.
Выделение определяет объекты; без выделения — сведения о текущей папке.
Текущая папка, выбранная запись и внешние архивные уровни имеют отдельный
смысл. Сведения о внешнем архиве не должны перезаписывать свойства записи.

Прочитаны текущие тела [сборщика свойств](../../../src/filemanager/panels/PanelProperties.cpp),
[ListView-представления и копирования](../../../src/dialogs/listview/ListViewDialog.cpp),
а также FSFolderProperties и оригинальные CPanel::Properties/ListViewDialog.rc
из локального source archive. Исходный сборщик поддерживает отдельную запись,
агрегаты выбора, свойства папки, raw-свойства и несколько уровней архивов.
Эти сведения сохраняем, меняя группировку и Qt-представление. Алгоритмы
чтения свойств и обхода папок не заменяем новым HTML-подобным вычислением.

Для будущей реализации нужна типизированная проекция свойств с принадлежностью
к выбранному объекту/папке/уровню архива, состоянием известности и исходным
значением. Не восстанавливаем эту структуру по локализованным подписям и
строкам-разделителям готового отчёта. Неизвестные свойства reader сохраняются
в дополнительных сведениях; новое оформление не должно терять их.

В Windows обычные файлы сейчас используют системные Properties; архивные
сведения и Unix fallback — локальное представление. Макет показывает новую
форму сведений приложения, а не доказательство замены Windows shell sheet.
Платформенную границу нужно явно определить при реализации. В текущей
дизайн-итерации системные редакторы свойств не удаляются.

## Проверки

Перед реализацией сверить [действующий контракт](../../../docs/ui-layout-contracts/dialogs.md#selected-properties)
с новым согласованным вариантом. Старые геометрические требования не являются
приёмкой новой компоновки. Проверки должны защищать полноту значений и
принадлежность свойств, а не текущий набор строк или расположение виджетов.

Нужны поведенческие проверки: один/несколько объектов, неизвестный размер и
частичный результат, вложенный архив, полное копирование сведений,
возврат фокуса, изменение/исчезновение источника, независимые окна сведений.
Для интерфейса — normal/compact, длинные значения, клавиатура и доступность.

В HTML используются демонстрационные метаданные. Из главного окна берутся имя,
тип и доступные поля выбранных строк; технические поля не синтезируются.
Нативные системные свойства, VoiceOver и реальная работа с файлами этим не
проверены. При проектировании использована локальная выжимка macOS HIG,
проверенная 18 октября 2026; живую страницу Apple прочитать инструментом
полностью не удалось. Макет не объявляется подтверждённым соответствием HIG.
