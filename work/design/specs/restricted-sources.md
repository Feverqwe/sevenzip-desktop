# Ключи fscrypt и подключения для чтения

Статус: проработано автономно по поручению пользователя 5 ноября 2026.
Формы используют [общую компонентную систему](design-system.md).
Qt-реализация не изменена. В HTML нет реального доступа к устройству,
расшифровки или системного подключения.

## Ключи файловой системы

Форма fscrypt содержит источник, коллекцию ключей и действия «Без ключей»,
«Отмена», «Открыть». Один ключ по умолчанию, следующие добавляются явно.
Версия определяет необходимость дескриптора, но её переключение не уничтожает
введённые значения. Показ раскрывает только мастер-ключи; доступный фокус и
значение сохраняются. Дескриптор — отдельное поле идентичности ключа.

Валидация следует текущему FscryptKeyDialog::serialize: raw key имеет допустимый
диапазон целых байтов hex, пробелы допустимы; v1 требует дескриптор и не допускает
повторяющиеся дескрипторы. Ошибка указывает строку ключа, не повторяя секрет.
v2 не требует ручного дескриптора. Это не поле пароля: к нему нельзя применять
общие правила обработки текста из парольного запроса.

Корректный синтаксис не доказывает, что ключ подходит к данным. Решение о
доступном содержимом принимает reader. «Без ключей» оставляет доступную часть
только для чтения; зашифрованные имена скрыты, зашифрованные файлы недоступны.
Не показываем успешную расшифровку по факту заполнения поля. Отмена возвращает
в прежний контекст. Ключи не сохраняются как черновики макета, в сессии или
отчёте; закрытие формы освобождает текущий ввод.

Прочитан полный [FscryptKeyDialog](../../../src/crypto/fscrypt/fscryptkeydialog.cpp).
В HTML проверены смена версии с сохранением ключа, duplicate v1 descriptor,
недоступность «Открыть» при ошибке, Cancel/reopen с пустыми полями и компактная
форма. Валидация/криптография будущей реализации остаются за native владельцем.

## Подключение

Подключаем текущую папку источника только для чтения. Одна контекстная форма
показывает подготовку, ошибку либо готовые параметры. Нужда в кэше определяется
reader, а не свободным переключателем пользователя. Для прямого чтения лимит
кэша не показывается. Для извлечения по запросу указываем лимит и коротко
объясняем освобождение старого кэша и невозможность прочитать один файл,
превышающий лимит. Подробная справка не возвращается.

Необязательный ввод подписан «Пароль архива». Это не пароль системного
подключения; служебные transport credentials генерирует существующий владелец
сессии и не выставляет пользователю. Секрет не сохраняется как обычный draft.
Подготовка показывает простой прогресс и отмену, без времени/счётчиков.
«Подключить» недоступно до готовности и при неверном лимите. При отмене native
подготовка должна завершить работу до освобождения используемых объектов.

## Разрешения чтения

Разрешение извлечения в кэш и согласие использовать непроверенный вывод — разные
вопросы. В обоих есть конкретный источник, последствия, «Отмена» и действие
с точным названием. Начальный фокус на отмене. Первое решение действует на
извлечение файлов выбранного подключения, включая повтор после вытеснения
из кэша. Его отмена запрещает извлечение до нового подключения, не обещает
отключить уже подключённую папку. Непроверенный вывод остаётся явно
непроверенным; согласие не исправляет архив и не превращает ошибку в успех.

## Менеджер подключений

Немодальный список сессий показывает источник, путь и состояние. Действия
относятся к выбранной сессии: открыть папку, скопировать полный путь, отключить.
Закрытие менеджера не отключает источник. Подготовку можно отменить.
Отключённую запись можно убрать из списка, не удаляя исходные данные.

Принудительное отключение появляется после неудачного обычного отключения
активной сессии. Оно требует отдельного подтверждения с предупреждением о
других приложениях и фокусом на отмене. Не используем смену текста одной кнопки
вместо понятного вопроса. При отказе вопрос закрывается, подключение остаётся.
Реальный результат native unmount определяет переход к «Отключено»; UI не
должен заранее удалять неотключённую сессию.

Просмотрены [настройки подключения](../../../src/mount/qtmountsettings.cpp),
[менеджер](../../../src/mount/qtarchivemountmanagerdialog.cpp) и
[вопрос извлечения](../../../src/mount/qtmountextractionprompt.cpp).
Они сохраняют своих владельцев; source/view/session не переносятся в общий
визуальный компонент. HTML демонстрирует одну сессию и существенные состояния;
native список обязан сохранять несколько независимых сессий и их идентичность.

Проверки будущей реализации: отмена подготовки/поздний результат; direct/cache;
неверный лимит; пароль/ключи без утечек; решение в области одной сессии; ошибка
извлечения и непроверенные данные; несколько подключений; busy unmount,
отказ и подтверждение force; закрытие менеджера; clipboard длинного пути.
Платформенное подключение проверяется отдельно на затронутой ОС.
