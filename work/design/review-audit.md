# Аудит концепта перед передачей в реализацию

5 ноября 2026, ready-v55. Дизайн-пакет подготовлен для реализации: ниже различаются
проверенные материалы и работа будущей Qt-реализации. Основание — решения пользователя,
design-plan, сценарии, спецификации и актуальный checkout, а не только наличие
файлов или успешное отображение формы.

## Текущая native галерея

Выполнен scripts/capture-ui-review.py из design-concept с отдельным workspace
этой ветки и существующим общим compiler cache. Сборка lite, действующий Qt kit
6.12.0, Cocoa на macOS arm64. Никакой cache reset или чистой пересборки не было.
На текущем isolated workspace отсутствовало готовое дерево; необходимые outputs
созданы с повторным использованием существующего compiler cache. Сохранены
полезные incremental outputs, runtime и SFX.

84 запуска из 42 производителей, 1254 снимка, failed scenarios: 0.
Все записали revision e16690f70176d26b00b2ffdad4823ced96e8b8cb. Новая галерея
подключена в window-catalog; все прежние sourceReport ссылки существуют.
window-inventory заново получен из текущих widget JSON с их capture/revision
metadata. Source C++ не изменён, но capture config и три UI-fixture файла
содержат сохранённые изменения этой задачи; их diff/config fingerprint отмечен
в reviewFixtureState каталога. Это не «чистый коммит без локальных fixtures».

Вручную просмотрен текущий About: версия 0.1.13 и дата основы подтверждаются
снимком и JSON. Исходная галерея 4 ноября была снята на 21ae5193, поэтому
не могла подтверждать текущую базу. Это обнаруженное расхождение исправлено.
Новые concept-only виды, например licenses, не получают фиктивный native снимок.

После проверки нового набора и ссылок удалена только старая task-owned галерея
на 92 МБ. Активных capture процессов и ссылок текущего каталога на неё нет.
Новые снимки и полезные incremental build/runtime outputs занимают около 930 МБ
и сохранены для review и следующих проверок. Compiler cache не очищался.

Скриншоты доказывают полученные состояния выбранных производителей, а не полное
поведение движка, source-port completeness, системные панели ОС или Windows/Linux.
В этой задаче пользователь не запрашивал новую трёхплатформенную матрицу.

## Изменения, уже сделанные при аудите

- Удалён декоративный «Проект · 8 объектов»: он не соответствовал захваченному
  источнику многих форм. Заголовок родительского окна берётся из текущей вкладки.
- Обновлена база implementation-main-window: e16690f7 / 0.1.13 вместо старой
  оценки состояния ветки на 1052bd52. Историческая передача не выдаётся за свежую.
- В operation-progress различены уже существующий независимый 7zG launcher
  и in-process lifecycle файловых операций. Нельзя заново реализовывать
  процессный запуск, который появился в новой базе.
- Проверены относительные ссылки всех design Markdown: отсутствующих целей нет.

## Геометрия HTML

После удаления декоративного контекста выполнен наблюдаемый проход по 238
состояниям диалогов/меню в 480×640 dark. Ошибок JavaScript и горизонтального
переполнения нет; завершающие действия форм помещаются. Три menu представления
имеют menu surface вместо dialog title и оцениваются отдельно. Этот проход
проверяет компоновку, не заменяя реальные действия, source callbacks и native tests.
Главное окно, каталог компонентов и самостоятельные операции требуют своих
проверок взаимодействия; их нельзя считать проверенными этим одним проходом.

## Проверка команд и владельцев

Уточнение file-actions-v53: просмотр и редактор больше не открывают пример
отчёта. Обычные файлы публикуют разные review intents, записи архива/recovery
используют временную копию с запретом записи в read-only источник. Меню,
контекстные команды, toolbar и затронутые shortcuts используют общую проверку
контекста. Это ещё не утверждение об аудите всех клавиш и пунктов приложения.

Проверка архива получила захваченную область (выбранные записи, весь архив,
выбранные файловые источники), окно без назначения и перезаписи, пароль/память
и корректный текст остановки. Исправлен переход служебного state picker из
пустой папки в read-only архив: раньше сохранялся пустой provider без readonly.
Браузерная проверка повторила эту последовательность и подтвердила различную
доступность Copy/Move/Delete/Edit. Отдельно проверены обе архивные области,
список двух файлов с исходными путями, остановка и неполный итог; контекстное
меню и операция помещаются в 480×640 dark. Native C++ не изменялся и повторная
capture/build серия для HTML не запускалась.

Контракт и границы: [файловые действия](specs/main-window-actions.md).

Уточнение service-v54: исправлен Service как меню, добавлен захват текущей
внутренней папки для подключения. Quit больше не возвращает в main без эффекта:
есть выход без работы, подтверждение незапущенных форм, возврат к задачам и
отложенный выход с сохранением сессии до закрытия окон. Сворачивание операции
без файловых окон не создаёт Home. Ошибочный результат удерживается до закрытия,
новое файловое окно отменяет отложенный выход. Прочитаны полные native launcher,
process/endpoint/reaper и MainWindow close; различие самостоятельного 7zG и
оконных in-process workers записано в [контракте](specs/application-lifecycle.md).
Браузером проверены эти переходы, повторный Quit, восстановление, занятой
benchmark, меню и alert в 480×640 dark. Native preflight mount/external owners
описан как требование реализации; HTML не подтверждает его выполнение.

Итог ready-v55 дополняет эти проверки:

- LocationBar сохраняет конечный пробел в отправленном пути; фокус адреса доступен
  из файлового окна. Меню и shortcut обновления используют один запрет загрузки.
  Пустой ввод не создаёт переход. Escape возвращает прежний путь.
- Возврат из свойств при множественном выборе ставит фокус на current item,
  даже если другая выбранная строка расположена раньше.
- В двух окнах созданы две самостоятельные операции. Решение конфликта одной
  не отвечает на пароль другой. Воспроизведён и исправлен сбой: фоновое завершение
  скрывало чужой вопрос. После исправления окно, ввод и фокус другого запроса
  сохраняются. Переключение и закрытие исходного файлового окна не пересоздаёт
  живой запрос; Escape удаляет поле запроса и переводит его операцию к остановке.
- Проверены общий каталог компонентов и состояния главного окна в компактном
  размере. Все 228 состояний остальных форм/меню повторно пройдены при 480×640
  dark и 1440×900 light: нет горизонтального переполнения и уходящих ниже окна
  завершающих действий. После корректной инициализации standalone review harness
  ошибок JavaScript нет. Этот проход геометрии не заменяет описанные выше
  взаимодействия или будущие native тесты.
- Настоящая страница index загружает макет и текущий native снимок; шапка при
  обычной ширине занимает одну строку (проверено 43,5 CSS px). Переключатель темы
  теперь меняет обе стороны сравнения и служебную область макета. Светлый режим
  проверен при системной тёмной теме, без тёмного фона под тёмными подписями.
- Все 43 native владельца inventory представлены в каталоге. Новые concept-only
  окна ссылаются на функционального владельца без выдуманного снимка. Help
  исключён из навигации, как и Windows-only интеграция Проводника на macOS.
  Все sourceReport и stateReport существуют, manifest содержит 84 запуска без
  error и 1254 capture. Версия галереи совпадает с базой design-worktree.
  Fingerprint текущих UI fixtures и capture config совпадает с сохранённым;
  native source остаётся неизменённым на e16690f7.
- 27 локальных текстов лицензий повторно сопоставлены с исходными байтами и SHA256:
  несовпадений нет. Это не индекс фактически установленного runtime-пакета;
  его формирование описано как задача реализации.
- Проверены Markdown-ссылки, JSON, идентичность source/preview и синтаксис JS;
  git diff --check проходит. Новые Qt-сборки для этих HTML-изменений не нужны.

Отдельный чат «Реализация нового главного окна Sevenzip» существует, использует
codex/main-window-design и читает живой макет из design-worktree; его поручение
и актуальный turn проверены read-only. Его код и результаты не выдаются за
интегрированные в e16690f7. План передачи ссылается на последние уточнения.
Обновлены устаревшие формулировки планов, миграция избранного и геометрия окон.

## Граница готовности

Все перечисленные продуктовые области имеют компоновку, действия, существенные
состояния, пользовательский сценарий и критерии реализации. Явная пользовательская
приёмка и автономные решения различаются в specs. Дальнейшие правки пользователя
могут менять дизайн; этот аудит завершает подготовку текущего набора, а не
замораживает интерфейс.

Следующий объём — Qt-реализация и её собственная приёмка: app-owned файловые
операции, общий lifecycle/guards, интеграции native pickers/mount/external,
миграция настроек, упаковка лицензий и платформенные проверки из specs.
Это не незаконченные дизайн-формы и не подтверждение готовности production.
Старые source audit документы не переписаны как обещание новой реализации.

Временные браузерные review-вкладки, direct HTML и одноразовые скрипты удалены.
Сервер 8768 оставлен для просмотра. Свежая галерея и полезные incremental
build/runtime outputs сохранены; общие кэши и чужие изменения не затронуты.
Коммиты, merge и push в дизайн-ветке не выполнялись.
